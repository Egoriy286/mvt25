# Лабораторная 6

[Код](lr6.py) — DOLFIN 2019. [Геометрия](mesh.geo) — Gmsh.

## По шагам

1. Gmsh строит квадрат 1×1 с грубой сеткой 10×10 и мелкими треугольниками.
2. Класс `Square(x, y, h)` задаёт квадрат: `(x, y)` — нижний левый угол, `h` — сторона. Через `.mark(...)` отмечаем 100 грубых ячеек.
3. Вокруг каждой вершины A выделяем все грубые ячейки, имеющие эту вершину. Внутри области их 4, на стороне 2, в углу 1. Всего `(10+1)² = 121` перекрывающаяся подобласть. `SubMesh(mesh, Square(...))` выделяет только существующие треугольники, поэтому у границы окрестность обрезается по области.
4. Встроенный класс DOLFIN `DomainBoundary` отмечает внешний контур подобласти числом 3. Затем `Side(0, ax)` ставит метку 1 на вертикальной линии через A, а `Side(1, ay)` — метку 2 на горизонтальной. В `Side.inside` не требуем `on_boundary`, поскольку эти линии проходят внутри подобласти. Если A лежит на границе всей области, соответствующая линия совпадает со стороной внешнего контура и получает метку 1 или 2.
5. Соседние ячейки отмечаем числами 1–4 и выделяем каждую через `SubMesh`. Это номера положений относительно A: нижняя левая, нижняя правая, верхняя левая, верхняя правая. У граничных вершин часть позиций отсутствует, их пропускаем. Всего сохраняется `81*4 + 36*2 + 4*1 = 400` составных ячеек с повторениями между подобластями.
6. Всей границе ячейки ставим 3. Один класс `Side(axis, value)` выбирает сторону: `Side(0, ax)` — вертикальную через A (метка 1), `Side(1, ay)` — горизонтальную через A (метка 2).
7. Записываем подсетки и метки через `<<`. DOLFIN сам нумерует шаги времени.

В `MeshFunction` размерность 2 означает треугольники, 1 — рёбра. Начальная метка 0 остаётся на внутренних рёбрах.

## Сохранение

Файл создаётся один раз перед циклом, затем в него записываются все подобласти:

```python
omega = File(str(results / 'omega.pvd'))
# Внутри цикла:
omega << omega_i
omega_boundary << patch_boundary
```

Чтобы код был простым, сетки и метки границ сохраняются в отдельных общих PVD. Все файлы находятся в `results/`:

| Файл | Что содержит | Шаги |
|---|---|---|
| `omega.pvd` | Подобласти вокруг всех вершин | 0–120 |
| `omega_boundary.pvd` | Линии через A с метками 1, 2 и остальной внешний контур с меткой 3 | 0–120 |
| `omega_cells.pvd` | Метки соседних ячеек в каждой подобласти | 0–120 |
| `cells.pvd` | Отдельные составные ячейки | 0–399 |
| `cell_boundaries.pvd` | Их границы с метками 1, 2, 3 | 0–399 |
| `domains.pvd` | Метки 100 грубых ячеек всей области | 0 |

В ParaView открыть нужные PVD вместе и нажать **Apply**. Для подобласти и её границ время совпадает; для окраски линий выбрать поле `omega_boundary`. Чтобы поверхность подобласти не закрывала линии, скрыть `omega.pvd` или уменьшить его непрозрачность. Для отдельной ячейки открыть `cells/cells.pvd` и `cells/cell_boundaries.pvd`; для окраски границ выбрать поле `boundary_id`.

Для A = (0.5, 0.5) подобласть находится на шаге 60, её четыре отдельные ячейки — на шагах 198–201. У разных подобластей разное число ячеек, поэтому шаг в `cells.pvd` считается отдельно. Шаг обозначает номер объекта, а не физическое время. PVD нужно хранить вместе с соседними VTU-файлами.

## Почему учитываются граничные вершины

В статье Efendiev, Galvis, Hou, [Generalized Multiscale Finite Element Methods (GMsFEM)](https://arxiv.org/html/1301.2866), раздел 2, формула (5), окрестность вершины определяется как объединение всех грубых элементов, для которых она является вершиной. Применение этого определения к квадратной сетке даёт три случая:

| Где находится A | Число вершин | Ячеек в одной окрестности |
|---|---|---|
| Внутри области | 81 | 4 |
| На стороне, кроме углов | 36 | 2 |
| В углу | 4 | 1 |

В задании не сказано исключать вершины на границе. Поэтому здесь строим окрестности всех 121 вершин. Это объединение площадей ячеек с общей вершиной A; соседние окрестности перекрываются.

В отдельных постановках авторы явно берут только внутренние узлы. Например, Chung, Pollock, Pun, [Online basis construction for goal-oriented adaptivity in the GMsFEM](https://arxiv.org/html/1812.02290), раздел 1, рассматривают нулевые условия Дирихле и задают число узлов как число внутренних грубых узлов. Это дополнительное ограничение конкретной постановки; в этой лабораторной строим геометрию вокруг всех вершин.
